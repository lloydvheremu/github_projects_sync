This module imports the issues of a GitHub repository as tickets of the
OCA `Helpdesk
Management <https://github.com/OCA/helpdesk/tree/19.0/helpdesk_mgmt>`__
module (``helpdesk.ticket``), and keeps them up to date with a scheduled
job.

A Helpdesk team is linked to one GitHub repository. Every issue becomes
a ticket of that team and is updated on later runs. Pull requests are
skipped.

+--------------------+-------------------------------------------------+
| GitHub             | Helpdesk ticket                                 |
+====================+=================================================+
| Title              | Title                                           |
+--------------------+-------------------------------------------------+
| Body               | Description (plain text). A placeholder is used |
|                    | when the body is empty, because the description |
|                    | is required                                     |
+--------------------+-------------------------------------------------+
| Labels             | Tags (reused by name, created when missing)     |
+--------------------+-------------------------------------------------+
| Assignees          | Assigned user: the first assignee whose GitHub  |
|                    | Login matches a user allowed on the team        |
+--------------------+-------------------------------------------------+
| Open / reopened    | The team's first open stage, or the stage       |
|                    | chosen on the team                              |
+--------------------+-------------------------------------------------+
| Closed             | The team's first closed stage, or the stage     |
|                    | chosen on the team                              |
+--------------------+-------------------------------------------------+
| Number, URL, state | Read-only GitHub tab on the ticket              |
+--------------------+-------------------------------------------------+

GitHub is the source of truth: changes made in Odoo to the title,
description, tags and assignee are overwritten the next time the issue
changes on GitHub. Creating tickets does not notify the assignee.

Configuration
=============

To configure this module, you need to:

1. Install the Python dependency: ``pip install requests``.

2. Create a GitHub `fine-grained personal access
   token <https://github.com/settings/personal-access-tokens>`__ with
   read-only access to *Issues* on the repositories you want to sync.
   For public repositories the token is optional, but GitHub then allows
   only 60 requests per hour.

3. Go to *Settings > Helpdesk > GitHub* and paste the token. It is
   stored as a system parameter that only administrators can read.

   |Token setting|

4. Optional: open a user (*Settings > Users & Companies > Users*), go to
   the *Preferences* tab and set the *GitHub Login*. Issues assigned to
   that GitHub account are then assigned to this user. The login is
   unique, ignoring case.

   |GitHub Login on the user|

Usage
=====

To link a team to a repository:

1. Go to *Helpdesk > Configuration > Teams* and open a team. You must be
   a Helpdesk manager.

2. Open the *GitHub* tab, enter the repository as ``owner/name`` and
   tick *Sync with GitHub*. Optionally choose the stage for open issues
   and the stage for closed issues. Without a choice, the team's first
   open and first closed stages are used.

   |GitHub tab of the team|

3. Click *Sync now*, or wait for the hourly scheduled action *Helpdesk:
   Sync GitHub issues*. A notification shows how many tickets were
   created and updated.

   |Sync now|

4. The issues are now in *Helpdesk > Tickets*, with their labels as
   tags.

   |Imported tickets|

5. Open a ticket and use its *GitHub* tab to see the issue number, a
   link to the issue, its state and the time of the last sync.

   |GitHub tab of the ticket|

Running the sync again never creates duplicates, even if a ticket was
archived. If GitHub returns an error (bad token, rate limit, repository
not found, timeout), it is posted in the team's chatter and the last
sync time is not advanced, so the next run fetches the same issues
again.

Known issues / Roadmap
======================

- Send changes made in Odoo back to GitHub (two-way sync, planned for
  v2).
- Webhooks, so updates arrive immediately instead of with the next run.
- Set the ticket's customer (``partner_id``) from the GitHub author.
- A ticket has a single assigned user, so only one GitHub assignee is
  used.
- Render the Markdown of issue bodies and import issue comments.
- One token for the whole database, not one per team or per user.
- Sync GitHub Projects boards (GraphQL API).
